Phần 1: Nền Tảng Cú Pháp JS, TS, Node.js & React 19 Trong Mã Nguồn

Hướng dẫn bóc tách chi tiết từng cấu trúc ngữ pháp JavaScript, TypeScript, Node.js và React 19 được áp dụng trực tiếp trong mã nguồn dự án p2p-multiple-groups, có trích dẫn số dòng và giải thích lý do thiết kế từ gốc rễ.

💡
Tôn chỉ tài liệu

Tài liệu được viết bằng tiếng Việt dễ hiểu nhưng giữ nguyên toàn bộ từ khóa cú pháp tiếng Anh (như interface, type, async/await, useEffect) và định danh hàm/biến thực tế trong repository để bạn dễ dàng tra cứu và trả lời tự tin trong các buổi vấn đáp kỹ thuật.

1. Cú pháp JavaScript cốt lõi

Toàn bộ logic của p2p-multiple-groups được vận hành trên nền tảng JavaScript hiện đại (ECMAScript 2022+). Dưới đây là những cơ chế cú pháp nền tảng xuất hiện xuyên suốt mọi file trong dự án.

1.1. Khai báo biến (const vs let) và phạm vi khối (Block Scope)

Trong codebase, từ khóa cổ điển var bị loại trừ hoàn toàn. Hai từ khóa sau đây phân chia ranh giới rõ ràng:

  • const: Tạo một liên kết bất biến (immutable binding). Biến không thể bị gán lại bằng dấu =, nhưng các phần tử bên trong một Map, Set hay thuộc tính của Object vẫn có thể thay đổi được (mutable content).
  • let: Dùng khi giá trị biến cần được gán lại trong tương lai (ví dụ: cờ trạng thái, con trỏ thời gian, hoặc hàng đợi Promise nối đuôi).
// Trích xuất từ src/main/p2p/credential-store.ts
export class SafeCredentialStore implements CredentialStore {
  private readonly filePath: string                          // const field ở cấp class
  private readonly memoryCache = new Map<string, string>()  // Map không thể bị gán đè, nhưng có thể gọi .set()
  private isLoaded = false                                   // Cờ trạng thái cần gán lại
  private queue: Promise<void> = Promise.resolve()           // Hàng đợi Promise được gán nối đuôi
}

Phạm vi khối (Block Scope): Cả const và let đều bị giới hạn nghiêm ngặt bên trong cặp ngoặc nhọn { ... } của lệnh if, vòng lặp for hay khối try/catch. Sau khi ra khỏi khối, biến sẽ tự động được giải phóng khỏi tầm vực.

1.2. So sánh nghiêm ngặt (===, !==) và chân trị (Truthiness/Falsiness)

Dự án tuyệt đối không dùng toán tử so sánh lỏng lẻo == và != nhằm loại trừ hiện tượng ép kiểu ngầm định (Type Coercion Hazards) của JavaScript (chẳng hạn 0 == '' trả về true nhưng 0 === '' trả về false).

  • Falsy values trong JavaScript bao gồm chính xác 6 giá trị: false, 0, -0, "" (chuỗi rỗng), null, undefined, và NaN.
  • Mọi giá trị khác, bao gồm mảng rỗng [] và đối tượng rỗng {}, đều là Truthy!
// src/shared/p2p.ts
export function validateDisplayName(name: string): ActionResult {
  const trimmed = name.trim()
  // Kiểm tra truthiness: trimmed rỗng ("") là falsy!
  if (!trimmed) {
    return { ok: false, code: 'INVALID_ARGUMENT', message: 'Display name cannot be empty' }
  }
  // So sánh nghiêm ngặt độ dài tối đa 32 ký tự
  if (trimmed.length > 32) {
    return { ok: false, code: 'INVALID_ARGUMENT', message: 'Display name exceeds 32 characters' }
  }
  return { ok: true }
}

1.3. Đoản mạch logic (&&, ||), Nullish Coalescing (??) và Optional Chaining (?.)

Nullish Coalescing (??) vs Logic OR (||): Toán tử ?? chỉ kích hoạt giá trị dự phòng nếu toán tử bên trái là null hoặc undefined. Nếu toán tử bên trái là 0 hoặc "", ?? vẫn bảo tồn giá trị bên trái (không bị nhầm lẫn như ||). 

// src/main/p2p/credential-store.ts:176
async getCredential(groupKey: string): Promise<string | null> {
  return this.queueOperation(async () => {
    // Nếu memoryCache không có key, .get() trả về undefined. ?? null chuyển thành null.
    return this.memoryCache.get(groupKey) ?? null
  })
}

Optional Chaining (?.) và Optional Call (?.()): Truy cập thuộc tính hoặc thực thi hàm an toàn mà không làm crash ứng dụng khi gặp null hoặc undefined. 

// 1. Gọi hàm tùy chọn (Optional function call) trong src/main/menu.ts:13
// Nếu commandHandler là null, không làm gì cả, không báo lỗi "is not a function"
commandHandler?.(command)

// 2. Gọi callback từ React component props trong src/renderer/src/features/search/Search.tsx:60
const handleGroupChange = (newGroupKey: string) => {
  onSelectGroup?.(newGroupKey)
}

// 3. Đọc thuộc tính lồng nhau: grp.search có thể là undefined
const defaultQuery = grp.search?.query ?? ''

1.4. Template Literals, Object Shorthand và Destructuring Assignment

  • Template Literals (`${...}`): Cho phép nội suy biểu thức linh hoạt: 
    // src/main/theme-store.ts:41
const tempPath = `${filePath}.${randomUUID()}.tmp`
  • Object Property Shorthand: Khi tên biến trùng với tên thuộc tính: { theme } tương đương { theme: theme }.
  • Destructuring Assignment: Phân rã mảng và đối tượng: 
    // Trích xuất mảng: lấy state và updater trong React
const [queryInput, setQueryInput] = useState('')

// Trích xuất đối tượng từ gói tin
const { groupId, peerId, payload } = message

1.5. Arrow Functions và các phương thức mảng bậc cao

Codebase áp dụng triệt để các hàm mảng bậc cao bất biến (Immutability), giúp mã nguồn ngắn gọn và trực quan:

Phương thức Ví dụ trong Codebase Mục đích sử dụng
.filter() peers.filter((p) => p.supernodeEligible) (election.ts:11) Lọc ra danh sách các peer có bật cờ ứng cử viên Supernode.
.sort() eligible.sort((a, b) => a.joinOrder - b.joinOrder || a.peerId.localeCompare(b.peerId)) Sắp xếp ưu tiên thời điểm vào nhóm (joinOrder), hòa điểm thì so sánh từ điển peerId.
.every() tokens.every((token) => normalizedName.includes(token)) (search-index.ts:45) Thực hiện phép VÀ logic (Boolean AND): tên file phải chứa toàn bộ từ khóa tìm kiếm.
.some() transfers.some((t) => t.state === 'transferring') Kiểm tra xem có bất kỳ tiến trình tải file nào đang chạy hay không.
.find() groups.find((g) => g.groupKey === newGroupKey) Tìm nhóm đầu tiên khớp với khóa groupKey đã chọn.
.map() peers.map((p) => p.peerId) Trích xuất danh sách mã định danh peerId từ danh sách đối tượng peer.

2. ES Modules và Dynamic Imports

2.1. Named Exports, Default Exports và Type-Only Imports (import type)

Dự án đặt "type": "module" trong package.json. Mọi file nguồn đều là chuẩn ECMAScript Modules (ESM).

  • Named Exports (export function ...): Giúp trình gom mã (Bundler) loại bỏ mã chết không dùng tới (Tree-shaking).
  • Default Exports (export default function App()): Dành cho component chính của React.
  • Type-Only Imports (import type { SafeStorage } from 'electron'): Yêu cầu bắt buộc bởi cờ "erasableSyntaxOnly": true trong tsconfig.node.json.
⚡
Tại sao bắt buộc dùng `import type` trong Node.js 24?

Node.js >=24 có tính năng Native Type Stripping (chạy trực tiếp file .ts không qua bước build). Nó hoạt động bằng cách thay thế các khai báo kiểu TypeScript bằng khoảng trắng trong bộ nhớ RAM. Nếu bạn import một interface mà không có từ khóa type, Node.js sẽ nghĩ đó là một biến JavaScript thực tế và quẳng lỗi SyntaxError / ReferenceError lúc thực thi!

2.2. Dynamic Import với Top-Level Await trong môi trường lai

File src/main/p2p/credential-store.ts được chia sẻ giữa môi trường Electron Desktop thật (có module electron.safeStorage) và môi trường kiểm thử Node.js thuần (không có Electron binary). Kỹ thuật Dynamic Import trong khối try/catch giúp giải quyết triệt để vấn đề: 

// src/main/p2p/credential-store.ts:33-42
let electronSafeStorage: SafeStorage | null = null

try {
  // Nạp động thư viện 'electron' khi module được load vào RAM
  const electron = await import('electron')
  if (electron && typeof electron === 'object' && 'safeStorage' in electron && electron.safeStorage) {
    electronSafeStorage = electron.safeStorage as SafeStorage
  }
} catch {
  // Trong Node.js test runner thuần, khối catch bắt lỗi êm đềm
  // Hệ thống tự động chuyển sang fallback lưu trữ trên bộ nhớ RAM (memoryCache)!
}

3. Hệ thống kiểu dữ liệu TypeScript trong Project

3.1. interface vs type aliases

  • interface: Định nghĩa khuôn mẫu đối tượng (Object Shapes), hỗ trợ kế thừa qua extends (ví dụ: GroupInvitation, GroupRuntime).
  • type: Dùng cho tập hợp hội (Union Types), kiểu nguyên thủy hoặc kết hợp phức tạp (ví dụ: P2pErrorCode, ActionResult).

3.2. Literal Types và Tagged / Discriminated Unions

Discriminated Unions (Tagged Unions) là mô hình kiến trúc cốt lõi để bảo đảm an toàn dữ liệu trên mạng WebRTC và IPC. Mọi thông điệp đều chứa một thuộc tính nhãn (Discriminant Tag như ok hoặc type): 

// src/shared/p2p.ts
export type ActionResult<T = void> =
  | { ok: true; data: T }
  | { ok: false; code: P2pErrorCode; message: string }

Khi kiểm tra if (!result.ok), trình biên dịch TypeScript tự động hiểu rằng tại nhánh đó biến result chắc chắn có chứa các trường code và message: 

const result = await window.p2p.joinGroup(options)
if (!result.ok) {
  // TypeScript tự động thu hẹp kiểu (Type Narrowing)
  console.error(`Thao tác thất bại [${result.code}]: ${result.message}`)
  return
}
// Tại đây TypeScript biết kết quả thành công và result.ok === true!

3.3. Intersection Types và readonly Modifiers

Toán tử & cho phép gộp các kiểu dữ liệu lại với nhau: MultiGroupP2pState & P2pState. Từ khóa readonly bảo vệ danh sách peer hoặc mảng cấu hình không bị đột biến vô ý: 

// src/main/p2p/election.ts:10
export function electSupernodes(peers: readonly SignalingRosterPeer[]): ElectionResult {
  // peers.push(...) -> BÁO LỖI BIÊN DỊCH NGAY LẬP TỨC!
}

3.4. Const Assertions (as const) và Indexed Access Types

// src/renderer/src/features/commands/commands.ts
export const COMMAND_DESCRIPTORS = [

3.5. Utility Types trong Codebase

Các tiện ích kiểu chuẩn của TypeScript được tận dụng tối đa:

  • Partial<T>: Biến mọi trường thành tùy chọn (dùng trong Partial<ConnectOptions>).
  • Record<K, V>: Bản đồ tra cứu từ điển (ví dụ Record<string, GroupRuntime>).
  • Extract<T, U>: Trích xuất một nhánh cụ thể từ một Discriminated Union.
  • Parameters<typeof readFile>[0]: Trích xuất chính xác kiểu đường dẫn tập tin (PathLike) của Node.js.

3.6. Generics (<T>) trong Hàng đợi Bất đồng bộ

Hàm queueAction<T> trong src/main/p2p/engine.ts:1242 minh họa sức mạnh của Generic: 

function queueAction<T>(action: () => Promise<T>): Promise<T> {
  const enqueued = policyQueue.then(() => {
    if (isDisposed) {
      return Promise.reject(new Error('Engine disposed'))
    }
    return action()
  })
  policyQueue = enqueued.then(
    () => {},
    () => {}
  )
  return enqueued
}

3.7. unknown vs any và User-Defined Type Guards

Trong dự án, dữ liệu từ đĩa hoặc mạng luôn được gán kiểu unknown (an toàn) thay vì any (tắt kiểm tra kiểu). Để chuyển từ unknown sang kiểu dữ liệu cụ thể, ta dùng Type Guard Function: 

// src/shared/contracts.ts
export function isThemePreference(value: unknown): value is ThemePreference {
  return value === 'system' || value === 'light' || value === 'dark'
}

4. Bất đồng bộ, Promise và Concurrency Queues

4.1. Event Loop, Microtask Queue và Promise

JavaScript chạy đơn luồng (Single-threaded). Khi một Promise được giải quyết (resolved), callback của nó sẽ được đưa vào Microtask Queue. Hàng đợi Microtask luôn được dọn sạch trước khi Event Loop chuyển sang vẽ lại giao diện hoặc nhận sự kiện I/O tiếp theo (Macrotask).

4.2. Mẫu tuần tự hóa hàng đợi Promise (Promise Chain Serialization Pattern)

Để chống xung đột dữ liệu (Race Condition) khi nhiều thao tác mạng và đĩa diễn ra đồng thời, codebase dùng kỹ thuật nối đuôi Promise với 2 hàm rỗng nuốt lỗi: 

// Mấu chốt kỹ thuật:
policyQueue = enqueued.then(
  () => {}, // Fulfillment handler rỗng
  () => {}  // Rejection handler rỗng - NUỐT LỖI CHO ĐUÔI HÀNG ĐỢI!
)
⚡
Tại sao phải nuốt lỗi ở đuôi hàng đợi?

Nếu tác vụ số 1 thất bại và ném ra Exception, đuôi hàng đợi sẽ rơi vào trạng thái Rejected. Nếu không có hàm bắt lỗi rỗng ở bước 2, tác vụ số 2 xếp sau sẽ bị hủy bỏ liên đới do Promise trước nó bị lỗi! Việc gắn () => {} giúp bảo đảm hàng đợi luôn kết thúc ở trạng thái Fulfilled, trong khi người gọi tác vụ 1 vẫn nhận đủ lỗi qua biến enqueued.

4.3. Quản lý bộ đếm thời gian (Timers) và Trailing Throttle 200ms

Hàm dispatchStateToWindow trong src/main/index.ts:34-51 sử dụng kỹ thuật Trailing Throttle: 

let stateThrottleTimer: NodeJS.Timeout | null = null
let pendingStateSnapshot: (MultiGroupP2pState & P2pState) | null = null

function dispatchStateToWindow(state: MultiGroupP2pState & P2pState): void {
  pendingStateSnapshot = state
  if (!stateThrottleTimer) {
    stateThrottleTimer = setTimeout(() => {
      stateThrottleTimer = null
      if (pendingStateSnapshot && mainWindow && !mainWindow.isDestroyed()) {
        mainWindow.webContents.send(IPC_CHANNELS.P2P_STATE_CHANGED, pendingStateSnapshot)
        pendingStateSnapshot = null
      }
    }, 200) // Khóa nhịp 200ms chống nghẽn IPC
  }
}

5. Cấu trúc dữ liệu và Node.js Built-in APIs

5.1. Map, Set và dọn rác tự động với WeakMap

Trong services/signaling/server.ts:50: 

const upgradeGroupIdMap = new WeakMap<WebSocket, string>()

WeakMap chỉ giữ tham chiếu yếu (Weak Reference) tới đối tượng socket. Khi client ngắt kết nối và đóng socket, bộ gom rác (Garbage Collector) của Node.js sẽ tự động giải phóng socket khỏi RAM mà lập trình viên không cần gọi lệnh dọn dẹp thủ công, ngăn chặn 100% hiện tượng Memory Leak.

5.2. Nhị phân, Băm SHA-256, HMAC-SHA1 và So sánh hằng thời gian (timingSafeEqual)

  • Streaming SHA-256: Dùng createHash('sha256') đọc từng chunk 16 KiB để xử lý file tới 1 GiB mà không tốn RAM.
  • HMAC-SHA1: Sinh mật khẩu xác thực TURN tạm thời tuân thủ RFC 5766.
  • Chống tấn công thời gian (Timing Attack): Dùng timingSafeEqual(providedBuf, group.tokenBuffer) để kiểm tra token bí mật thay cho toán tử ===, loại bỏ nguy cơ bị lộ khóa do đo thời gian nano-giây.
