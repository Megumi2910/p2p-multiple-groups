Phần 2: Mã Nguồn Tầng Giao Tiếp Chung, Preload Bridge & Signaling Server

Mổ xẻ chi tiết kiến trúc đóng gói build bundler, hợp đồng IPC, bộ tiền kiểm định Zero-Trust, giao thức tầng dây nhị phân, cầu nối an ninh Preload và máy chủ định tuyến Signaling Server.

💡
Phạm vi module trong chương này

Các file được phân tích chuyên sâu: electron.vite.config.ts, src/shared/contracts.ts, src/shared/p2p.ts, src/shared/p2p-wire.ts, src/preload/index.ts, services/signaling/config.ts, services/signaling/server.ts, và scripts/create-invite.ts.

1. Cấu hình Build & Bundler (electron.vite.config.ts)

File electron.vite.config.ts là trung tâm điều phối toàn bộ việc biên dịch 3 tiến trình Electron thông qua một file cấu hình duy nhất: 

// electron.vite.config.ts:19-51
export default defineConfig(({ command }) => {
  const isDev = command === 'serve'

  return {
    main: {
      build: {
        rollupOptions: {
          output: {
            format: 'es',              // Tiến trình chính xuất ra chuẩn ES Module
            entryFileNames: 'index.js'
          }
        }
      }
    },
    preload: {
      build: {
        rollupOptions: {
          output: {
            format: 'cjs',             // Preload script xuất ra chuẩn CommonJS
            entryFileNames: 'index.cjs'
          }
        }
      }
    },
    renderer: {
      plugins: [react(), kazaaCsp(isDev)],
      server: {
        host: '127.0.0.1',             // Khóa chặt loopback cục bộ
        port: 5173,
        strictPort: true               // Không tự ý nhảy sang port khác nếu 5173 bận
      }
    }
  }
})

1.1. Plugin kazaaCsp(isDev) và cơ chế tiêm biến bảo mật %KAZAA_CSP%

Trong src/renderer/index.html, thẻ <meta> được định nghĩa sẵn một placeholder %KAZAA_CSP%. Plugin tùy biến kazaaCsp sử dụng hook transformIndexHtml của Vite để thay thế placeholder này tùy theo môi trường: 

// electron.vite.config.ts:5-17
function kazaaCsp(isDev: boolean): Plugin {
  // 1. Môi trường phát triển: Cần kết nối WebSocket HMR tới Vite Server
  const devCsp =
    "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ws://127.0.0.1:5173; object-src 'none'; base-uri 'none'; form-action 'none'"

  // 2. Môi trường phân phối (Production): CẤM HOÀN TOÀN MỌI KẾT NỐI MẠNG TỪ GIAO DIỆN
  const prodCsp =
    "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'"

  return {
    name: 'kazaa-csp',
    transformIndexHtml(html: string): string {
      return html.replace('%KAZAA_CSP%', isDev ? devCsp : prodCsp)
    }
  }
}
🛡️
Tại sao Production lại đặt `connect-src 'none'`?

Giao diện React chạy trong sandbox của Chromium. Khi đặt connect-src 'none', trình duyệt sẽ chặn đứng hoàn toàn mọi lời gọi fetch(), XMLHttpRequest, hay new WebSocket() từ giao diện. Dù có kẻ tấn công chèn mã XSS, mã độc cũng không thể bí mật tuồn dữ liệu người dùng ra ngoài Internet!

3. Kiểu miền dữ liệu & Bộ tiền kiểm định đầu vào (src/shared/p2p.ts)

3.1. Mã lỗi chuẩn P2pErrorCode và ActionResult

Mọi thao tác trong hệ thống đều trả về kiểu phân biệt ActionResult với 14 mã lỗi định danh thống nhất: 

// src/shared/p2p.ts:1-18
export type P2pErrorCode =
  | 'INVALID_INPUT'        // Tham số sai cú pháp hoặc vượt giới hạn
  | 'AUTH_FAILED'          // Sai token mật mã nhóm
  | 'DISCONNECTED'         // Mất kết nối tới Signaling Server hoặc peer
  | 'NO_SUPERNODE'         // Nhóm chưa bầu chọn được Supernode đại diện
  | 'UNREACHABLE'          // Không thể xuyên thủng NAT để tạo kênh WebRTC
  | 'NOT_FOUND'            // Không tìm thấy file hoặc nhóm yêu cầu
  | 'FILE_CHANGED'         // File chia sẻ bị thay đổi trong lúc đang truyền
  | 'DESTINATION_EXISTS'   // Tên file tải về đã tồn tại trên đĩa máy nhận
  | 'IO_ERROR'             // Lỗi đọc/ghi ổ cứng cục bộ
  | 'BUSY'                 // Hệ thống đang bận thực thi tác vụ khác
  | 'PROTOCOL_ERROR'       // Gói tin sai cấu trúc giao thức
  | 'FORBIDDEN'            // Quyền truy cập bị từ chối
  | 'INVITATION_REQUIRED'  // Chưa nạp mã mời của nhóm

export type ActionResult<T = void> =
  | { ok: true; data: T }
  | { ok: false; code: P2pErrorCode; message: string }

3.2. Cấu trúc và kỹ thuật tuần tự hóa GroupKey

Để hỗ trợ đa nhóm trên nhiều máy chủ khác nhau mà không bao giờ bị trùng lặp định danh, hệ thống gom cặp [signalingUrl, groupId] thành một chuỗi JSON chuẩn: 

// src/shared/p2p.ts:34-56
export type GroupKey = string

export function makeGroupKey(signalingUrl: string, groupId: string): GroupKey {
  return JSON.stringify([signalingUrl, groupId])
}

export function parseGroupKey(key: string): { signalingUrl: string; groupId: string } | null {
  if (typeof key !== 'string') return null
  try {
    const parsed = JSON.parse(key) as unknown
    if (
      Array.isArray(parsed) &&
      parsed.length === 2 &&
      typeof parsed[0] === 'string' &&
      typeof parsed[1] === 'string'
    ) {
      return { signalingUrl: parsed[0], groupId: parsed[1] }
    }
  } catch {
    // Không quăng lỗi, trả về null nếu format sai
  }
  return null
}

3.3. Các hàm tiền kiểm định nghiêm ngặt (Zero-Trust Input Validators)

  • validateSignalingUrl: Chỉ cho phép wss: (hoặc ws: trên loopback cục bộ), bắt buộc pathname là /signal, cấm credentials và query parameters.
  • validateGroupId: Khớp biểu thức /^[A-Za-z0-9_-]{1,32}$/.
  • validateToken: Khớp Regex 43 ký tự base64url, giải mã bằng atob để bảo đảm chính xác **32 bytes dữ liệu nhị phân (256 bits entropy)** và kiểm tra tính chuẩn tắc (Canonical representation).
  • validateDisplayName: Giới hạn 1 đến 40 ký tự, loại bỏ khoảng trắng thừa và cấm ký tự điều khiển ẩn [\u0000-\u001F\u007F].
  • validateGroupInvitation: Hỗ trợ tự động chuyển đổi mã mời phiên bản cũ V1 sang cấu trúc V2.

Hằng số Giá trị Mục đích sử dụng

Mỗi lượt tải file mở một kênh dữ liệu riêng biệt để chống tắc nghẽn đường truyền điều khiển:

4.3. Type Guards phòng vệ tầng dây

Hàm isServerSignalingMessageV2 kiểm tra cấu trúc từng trường của dữ liệu JSON nhận từ mạng trước khi cho phép mã nguồn tiếp cận: 

// src/shared/p2p-wire.ts
export function isServerSignalingMessageV2(val: unknown): val is ServerSignalingMessageV2 {
  if (!val || typeof val !== 'object') return false
  const msg = val as Record<string, unknown>
  if (msg.v !== 2 || typeof msg.type !== 'string') return false
  // Kiểm tra chi tiết từng nhánh thông điệp: welcome, group-joined, roster, signal...
  return true
}

5. Cửa khẩu An ninh Preload Script (src/preload/index.ts)

5.1. Cơ chế đóng gói hàm IPC và Cleanup Closures

File src/preload/index.ts đóng gói ipcRenderer.invoke thành các phương thức typed rõ ràng và tạo các bộ lắng nghe sự kiện có khả năng dọn dẹp bộ nhớ: 

// src/preload/index.ts:25-35
onState(listener: (state: any) => void): () => void {
  const wrapped = (_event: IpcRendererEvent, state: any): void => {
    listener(state)
  }
  ipcRenderer.on(IPC_CHANNELS.P2P_V2_STATE, wrapped)
  ipcRenderer.on(IPC_CHANNELS.P2P_STATE, wrapped)

  // Trả về hàm hủy đăng ký (Cleanup Closure)
  return () => {
    ipcRenderer.removeListener(IPC_CHANNELS.P2P_V2_STATE, wrapped)
    ipcRenderer.removeListener(IPC_CHANNELS.P2P_STATE, wrapped)
  }
}

5.2. Kỹ thuật định tuyến chữ ký kép (Dual-Signature Routing)

Preload tự động phát hiện số lượng tham số để hỗ trợ cả lệnh gọi V2 và V1: 

// src/preload/index.ts:84-96
search(arg1: string, arg2?: string): Promise<ActionResult> {
  if (arg2 !== undefined) {
    // V2: search(groupKey, query)
    return ipcRenderer.invoke(IPC_CHANNELS.P2P_V2_SEARCH, arg1, arg2)
  }
  // V1: search(query)
  return ipcRenderer.invoke(IPC_CHANNELS.P2P_SEARCH, arg1)
}

5.3. Cô lập hoàn toàn môi trường với contextBridge.exposeInMainWorld

Hàm contextBridge.exposeInMainWorld('p2p', api) đóng băng đối tượng API, ngăn chặn mã giao diện React truy cập vào Node.js runtime hoặc sửa đổi các hàm hệ thống.

6. Dịch vụ Máy chủ Signaling & Công cụ CLI (services/signaling/*, scripts/create-invite.ts)

6.1. Phân giải cấu hình đa nguồn loadSignalingOptions trong config.ts

Đọc cấu hình từ biến môi trường với thứ tự ưu tiên: P2P_MULTIPLE_GROUPS_* > KAZAA_* > Biến Cloud mặc định (PORT, RENDER). Thẩm định tính duy nhất của từng nhóm thông qua hai tập hợp seenGroupIds và seenTokens.

6.2. Bộ điều phối createSignalingServer trong server.ts

  • Điểm cuối HTTP /healthz: Trả về 200 OK cho các bộ kiểm tra sức khỏe của hạ tầng Cloud.
  • Token-Bucket Rate Limiter: Mỗi socket được cấp tối đa 60 token, hồi phục 30 token/giây, chặn đứng các cuộc tấn công DoS làm tràn ngập tin nhắn.
  • So sánh hằng thời gian timingSafeEqual: So sánh buffer token nhóm bằng hàm timingSafeEqual để loại bỏ hoàn toàn nguy cơ Timing Attack.
  • Chứng thực TURN RFC 5766 HMAC-SHA1: Tự động sinh username và mật khẩu tạm thời có thời hạn 24 giờ cho các peer cần xuyên NAT qua relay TURN.
  • Quét nhịp tim (Heartbeat Sweep): Định kỳ mỗi 15 giây ping kiểm tra kết nối. Nếu socket không phản hồi sau 35 giây, server chủ động đóng kết nối và thông báo cập nhật danh sách thành viên (roster) cho các node còn lại.

6.3. Điểm khởi động dịch vụ và Trình tạo mã mời scripts/create-invite.ts

Lệnh CLI npm run signal:invite -- --group-id=nhom-a tự động phân tích tham số dòng lệnh và in ra chuỗi JSON lời mời nhóm tiêu chuẩn:
