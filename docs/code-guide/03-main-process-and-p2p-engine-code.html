03. Main Process & P2P Engine Core Walkthrough

In-depth walkthrough of src/main/index.ts, single-instance locking, 4-tier IPC sender validation, HRW consistent hashing supernode election, SafeCredentialStore hardware encryption, and PeerEngine policy serialization.

1. Main Process & IPC Security Boundaries (src/main/index.ts)

The Main process runs in a privileged Node.js environment. Key responsibilities include:

  • Single-Instance Lock: Prevents multi-instance corruption on peer-state.json.
  • Profile Migration: Migrates configurations from legacy profile locations to p2p-multiple-groups.
  • 4-Tier validateSender: Origin verification rejecting unauthorized or orphaned frames.
  • Trailing 200ms State Throttle: Coalesces MultiGroupP2pState updates before dispatching over IPC_CHANNELS.P2P_V2_STATE.
  • IPC Handlers: Exposes createGroup, rotateGroupInvite, and removeGroupMember.

2. Supernode Elections & Rendezvous Consistent Hashing (src/main/p2p/election.ts)

Supernodes are elected deterministically based on eligibility, ascending joinOrder, and lexicographical tie-breaking. Ordinary peers use Highest Random Weight (HRW) consistent hashing to select supervising supernodes, minimizing client churn when nodes depart.

3. Storage, Persistence & Hardware Encryption (src/main/p2p/*)

The storage subsystem features:

  • SafeCredentialStore: Uses OS-level keychains (Windows DPAPI, macOS Keychain) to encrypt group tokens and ${groupKey}:owner secrets. Falls back to in-memory caching during headless unit tests.
  • MultiGroupPeerStore: Writes state updates to .tmp files before committing via atomic file renames.

4. Shared Library & Inverted Search Indexing

LibraryManager scans local files, generates stat fingerprints, and streams files through SHA-256 hashers. Supernodes maintain an inverted index with Unicode NFKC normalization and Boolean AND query matching.

5. Signaling Client & Transport Multiplexing

SignalingClient manages active virtual group memberships with exponential backoff reconnection. TransportManager aggregates multiple virtual groups over a single RTCPeerConnection, resolving WebRTC glare collisions and dynamically toggling TURN relay modes.

6. Transfers & SCTP Sliding-Window Flow Control

File transfers operate over 16 KiB chunks with cumulative 256 KiB ACKs, a 512 KiB inflight cap, high/low watermark stream suspension, and atomic commit upon SHA-256 digest verification.

7. PeerEngine Orchestrator

PeerEngine coordinates subsystems via a serialized policyQueue, monitoring 6000ms freshness leases and dispatching state snapshots to the UI.
