Phần 4: Giao Diện Người Dùng React Renderer, Bảng Tra Cứu & Bộ Đề Vấn Đáp (Inquiry Test)

Mổ xẻ kiến trúc giao diện React 19 sandboxed, custom hook quản lý trạng thái đơn điệu, cơ chế gom cụm Swarm tìm kiếm, bảng tra cứu nhanh 30+ vị trí code trọng yếu, cùng ngân hàng 32 câu hỏi vấn đáp chuyên sâu phục vụ bảo vệ đồ án và phản biện kỹ thuật.

💡
Nội dung cốt lõi của phần này

Tài liệu bao gồm: (1) Walkthrough chi tiết từng file trong src/renderer/src/; (2) Bảng tra cứu ánh xạ 30+ cơ chế phân tán đến từng file và hàm cụ thể; (3) 32 câu hỏi & trả lời mẫu cho Inquiry Test / Viva Defense chia làm 4 nhóm A, B, C, D.

1. Khởi động Renderer & Custom Hook Quản lý State

1.1. Mở rộng giao diện toàn cục Window trong env.d.ts

Trong TypeScript, đối tượng window của trình duyệt mặc định chỉ chứa các hàm Web API tiêu chuẩn (document, fetch). Để TypeScript nhận diện các phương thức do Preload Script tiêm vào qua contextBridge, file src/renderer/src/env.d.ts áp dụng kỹ thuật Declaration Merging: 

// src/renderer/src/env.d.ts:1-9
/// <reference types="vite/client" />
import type { KazaaApi, P2pApi } from '../../shared/contracts.ts'

declare global {
  interface Window {
    p2p: P2pApi
    kazaa: KazaaApi
  }
}

Nhờ khối khai báo này, mọi React component trong giao diện có thể gọi window.p2p.joinGroup(...) hoặc window.kazaa.getTheme() với đầy đủ hỗ trợ tự động gợi ý mã (IntelliSense) và kiểm tra kiểu tĩnh mà không cần ép kiểu (window as any).

1.2. Điểm gắn kết React 19 trong main.tsx

File src/renderer/src/main.tsx sử dụng API ReactDOM.createRoot của React 19 kết hợp chế độ kiểm tra nghiêm ngặt <React.StrictMode>: 

// src/renderer/src/main.tsx:6-13
const rootElement = document.getElementById('root')
if (rootElement) {
  ReactDOM.createRoot(rootElement).render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  )
}

1.3. Custom Hook usePeerState (src/renderer/src/features/network/usePeerState.ts)

Hook usePeerState là cầu nối dữ liệu duy nhất giữa toàn bộ giao diện React và cỗ máy P2P chạy ngầm dưới Main Process:

  • Khởi tạo State ban đầu: Gọi bridge.p2p.getState() ngay khi component mount để lấy dữ liệu snapshot đầu tiên.
  • Lắng nghe sự kiện đẩy qua IPC: Gọi bridge.p2p.onState(applyState) để nhận các cập nhật trạng thái mới nhất từ Main Process.
  • Kiểm tra tính đơn điệu Revision (Monotonic Invariant): 
    // usePeerState.ts:63 & 83-88
const lastRevisionRef = useRef(0)

const applyState = (incoming: CombinedPeerState) => {
  if (incoming.revision >= lastRevisionRef.current) {
    lastRevisionRef.current = incoming.revision
    setState(incoming)
  }
}
    Dùng useRef lưu số revision gần nhất. Nếu một gói tin IPC bị trễ đến sau một gói tin có revision cao hơn, gói tin trễ sẽ bị bỏ qua, triệt tiêu hiện tượng giật lùi giao diện.
  • Tự động chọn nhóm mặc định (Auto Group Selection): 
    // usePeerState.ts:66-74
useEffect(() => {
  if (state.groups.length > 0) {
    if (!selectedGroupKey || !state.groups.some((g) => g.groupKey === selectedGroupKey)) {
      setSelectedGroupKey(state.groups[0].groupKey)
    }
  } else {
    setSelectedGroupKey(null)
  }
}, [state.groups, selectedGroupKey])
  • Gói gọn các hàm Action trong useCallback: Các hàm joinGroup, leaveGroup, search, download được bọc trong useCallback với dependency rỗng [] để giữ nguyên tham chiếu hàm, giúp các component con không bị re-render vô ích.

2.2. Phân hệ mạng Network.tsx

Nằm tại src/renderer/src/features/network/Network.tsx:

  • Giải mã mã mời nhóm: Khi người dùng dán chuỗi JSON lời mời vào textarea, hàm parseGroupInvitation(inviteInput) tự động phát hiện mã mời V2 hoặc V1 cũ, kiểm tra URL, GroupId, Token và hiển thị cảnh báo nếu mã mời không hợp lệ.
  • Bảng danh sách thành viên (Roster Table): Hiển thị các node trong nhóm, vai trò đắc cử (supernode với huy hiệu nổi bật hoặc ordinary), trạng thái kết nối WebRTC (direct hay relay), và nút gạt cho phép node tự ứng cử làm Supernode.

2.3. Phân hệ thư viện Library.tsx

Nằm tại src/renderer/src/features/library/Library.tsx:

  • Định dạng dung lượng chuẩn (formatBytes): Chuyển đổi số byte nhị phân thành KiB, MiB, GiB dễ đọc.
  • Thao tác tập tin: Gọi onAddFiles (mở hộp thoại native OS), onRescan (quét lại thư mục) và onRemoveFile.
  • Cấp quyền truy cập theo nhóm (Fine-Grained Group Grants): Mỗi hàng file hiển thị danh sách các checkbox tương ứng với các nhóm mà node đang tham gia. Khi tick hoặc bỏ tick, hàm onSetFileGroups(fileId, newGroupKeys) gửi danh sách khóa nhóm mới xuống Main Process để cập nhật quyền truy cập ngay lập tức.

2.4. Phân hệ tìm kiếm Search.tsx

Nằm tại src/renderer/src/features/search/Search.tsx:

  • Bộ chọn phạm vi nhóm (Group Scope Selector): Cho phép người dùng chọn tìm kiếm trong một nhóm cụ thể hoặc tìm kiếm trên nhóm hiện tại.
  • Gom nhóm Swarm (Swarm Aggregation): Gom các kết quả trùng mã băm và kích thước vào một đối tượng GroupedResult: 
    // Search.tsx:102-118
const groupedMap = new Map<string, GroupedResult>()
for (const item of currentSearch.results) {
  const key = `${item.file.sha256}:${item.file.size}`
  let group = groupedMap.get(key)
  if (!group) {
    group = {
      groupKey: key,
      sha256: item.file.sha256,
      size: item.file.size,
      primaryName: item.file.name,
      sources: [],
      selectedSourceIndex: 0
    }
    groupedMap.set(key, group)
  }
  group.sources.push(item)
}
  • Lựa chọn node tải (Source Selection): Người dùng có thể chọn tải file từ node nào trong danh sách các node cùng sở hữu file đó thông qua dropdown menu nguồn tải.

2.5. Phân hệ truyền file Transfers.tsx

Nằm tại src/renderer/src/features/transfers/Transfers.tsx:

  • Phân chia 2 vùng hiển thị: activeTransfers (đang truyền) và completedTransfers (kết thúc, lỗi, hoặc hủy).
  • Thanh tiến trình thực tế: Tính phần trăm % = (transferredBytes / totalBytes) * 100.
  • Huy hiệu đường truyền: Hiển thị rõ Direct (xuyên NAT thành công) hoặc Relayed (TURN) (đi qua máy chủ chuyển tiếp).
  • Thao tác điều khiển: Hỗ trợ nút Cancel hủy truyền tức thì và nút Search Again tìm nguồn tải mới nếu lượt tải thất bại.

2.6. Bảng điều khiển lệnh CommandPalette.tsx & Appearance.tsx

  • Appearance.tsx: Cho phép người dùng chọn giữa 3 giao diện: System Default, Dark Theme, hoặc Light Theme.
  • CommandPalette.tsx: Modal điều khiển nhanh sử dụng thẻ <dialog> native của HTML5:

4. Bộ đề vấn đáp chuyên sâu (Inquiry Test / Viva Defense Q&A Bank)

Dưới đây là bộ 32 câu hỏi và câu trả lời hoàn chỉnh được biên soạn đặc thù cho các buổi vấn đáp đồ án tốt nghiệp, phản biện kỹ thuật hoặc phỏng vấn Senior Engineer.

Nhóm A: Cú pháp JS, TypeScript & React 19 (8 câu)

❓
Câu 1: Sự khác biệt cơ bản giữa `interface` và `type` trong TypeScript là gì? Tại sao trong project này `ActionResult` dùng `type` còn `GroupInvitation` dùng `interface`?

Trả lời: interface dùng để định nghĩa hình dạng đối tượng (Object Shapes), hỗ trợ cơ chế hợp nhất khai báo (Declaration Merging) và kế thừa mở rộng (extends). Do đó, GroupInvitation hay GroupRuntime dùng interface vì chúng đại diện cho các thực thể có thể mở rộng thuộc tính.
Ngược lại, type có khả năng biểu diễn các kiểu phức tạp hơn: Union Types (A | B), Primitive Aliases, Tuples, và Mapped Types. ActionResult bắt buộc phải là type vì nó là một Tagged Union ({ ok: true } | { ok: false; code: ... }).

❓
Câu 2: Tagged / Discriminated Union hoạt động như thế nào trong `ActionResult` và các gói tin `ServerSignalingMessageV2`?

Trả lời: Tagged Union là tập hợp các interface có chung một trường nhãn định danh (như ok hoặc type) mang kiểu Literal Type. Khi lập trình viên kiểm tra nhãn này (ví dụ if (!res.ok) hoặc switch (msg.type)), TypeScript tự động thực hiện Type Narrowing: bên trong khối đó, trình biên dịch nhận biết chính xác các trường đặc thù của kiểu dữ liệu mà không cần ép kiểu thủ công.

❓
Câu 3: Toán tử `as const` mang lại lợi ích gì trong định nghĩa `IPC_CHANNELS` và `COMMAND_DESCRIPTORS`?

Trả lời: Khi không có as const, TypeScript suy diễn chuỗi thành kiểu string rộng. Khi thêm as const: (1) Mọi thuộc tính trở thành readonly; (2) Mọi giá trị chuỗi trở thành String Literal Type chính xác. Kết hợp với typeof, ta tự động trích xuất được kiểu dữ liệu chuẩn (như CommandId = (typeof COMMAND_DESCRIPTORS)[number]['id']), ngăn ngừa hoàn toàn lỗi gõ sai tên kênh IPC khi biên dịch.

❓
Câu 4: Phân tích cơ chế hoạt động của hàm `queueAction` trong `src/main/p2p/engine.ts`. Tại sao phải gắn hai hàm rỗng `enqueued.then(() => {}, () => {})`?

Trả lời: queueAction hiện thực hóa mẫu tuần tự hóa Promise (Promise Chain Serialization Pattern) để thực hiện tác vụ theo thứ tự và chống Race Condition. Hai hàm rỗng enqueued.then(() => {}, () => {}) dùng để cô lập lỗi: nếu tác vụ A bị lỗi (rejected), hàm rỗng ở đuôi sẽ nuốt lỗi này cho chuỗi hàng đợi tổng policyQueue, giúp hàng đợi luôn trở về trạng thái Fulfilled. Tác vụ B xếp sau không bị hủy liên đới, trong khi người gọi tác vụ A vẫn nhận đủ kết quả lỗi qua Promise trả về.

❓
Câu 5: Tại sao trong `usePeerState.ts` và `App.tsx` lại sử dụng `useRef` cho `lastRevisionRef` và `isSavingThemeRef` thay vì dùng `useState`?

Trả lời: Thay đổi giá trị useState sẽ kích hoạt React re-render lại giao diện. Trong khi đó, lastRevisionRef và isSavingThemeRef chỉ là các biến theo dõi kỹ thuật nội bộ (Internal State Trackers). Nếu dùng useState cho lastRevisionRef, mỗi khi mạng cập nhật revision, component sẽ bị re-render thừa dù giao diện không đổi. ref.current cho phép đọc/ghi giá trị mới ngay lập tức mà hoàn toàn không kích hoạt chu kỳ render.

❓
Câu 6: Trong hook `useEffect` của `usePeerState.ts`, tại sao bắt buộc phải trả về hàm Cleanup (`return () => unsubscribe()`)? Hậu quả nếu quên là gì?

Trả lời: Hàm Cleanup được React tự động gọi khi component unmount hoặc trước khi chạy lại effect mới. Hàm này gọi ipcRenderer.removeListener(...) để hủy nhận tin từ Main Process. Nếu quên Cleanup, mỗi lần component mount lại, một listener mới sẽ được tạo thêm trong khi listener cũ vẫn nằm trong RAM, dẫn tới rò rỉ bộ nhớ (Memory Leak) và các callback bị gọi lặp lại nhiều lần gây sai lệch dữ liệu.

❓

Câu 8: Điểm khác nhau giữa kiểu `any` và `unknown` trong TypeScript là gì? Dự án áp dụng `unknown` kết hợp User-Defined Type Guard như thế nào?

Trả lời: any tắt hoàn toàn hệ thống kiểm tra kiểu, dễ gây crash lúc chạy. unknown là kiểu an toàn: TypeScript cấm thao tác trên biến unknown cho tới khi kiểu được thu hẹp. Câu 14: Kỹ thuật ghi đĩa nguyên tử (Atomic File Write) qua file `.tmp` giải quyết rủi ro gì trong `peer-store.ts` và `theme-store.ts`?

Hàm gọi fileName.normalize('NFKC').toLowerCase() để đưa toàn bộ tên file và từ khóa về cùng một biểu diễn nhị phân chuẩn tắc, loại bỏ lỗi tìm không thấy file do khác biệt bộ gõ.
(2) Boolean AND: Chuỗi tìm kiếm được tách thành mảng các token. Hàm dùng tokens.every((token) => normalizedName.includes(token)) — file chỉ được xem là trùng khớp nếu tên của nó chứa đầy đủ tất cả các từ khóa tìm kiếm.

Câu 29: Cơ chế kiểm soát dòng chảy (Flow Control & Backpressure) trong quá trình truyền file qua WebRTC Data Channel được thiết kế như thế nào?

Trả lời: Để bảo vệ bộ đệm socket mạng không bị tràn RAM khi đọc file từ ổ SSD siêu tốc:
1. File được cắt thành các khối nhỏ 16 KiB (CHUNK_SIZE = 16384).
2. Bên nhận gửi thông điệp xác nhận tích lũy ack sau mỗi 256 KiB dữ liệu nhận được.
3. Bên gửi giám sát số byte chưa được xác nhận unacked = offset - lastAckedBytes.
4. Nếu unacked >= 512 KiB (MAX_UNACK_BYTES) hoặc bộ đệm socket vượt ngưỡng 256 KiB (HIGH_WATER_BUFFER), luồng đọc đĩa lập tức tạm dừng (stream.pause()).
5. Chỉ khi nhận được gói ack hoặc bộ đệm socket xả xuống dưới 128 KiB (LOW_WATER_BUFFER), luồng đọc mới được tiếp tục (stream.resume()).

Câu 30: Cơ chế "Thu hồi quyền chia sẻ tức thì giữa chừng" (Mid-Transfer Revocation) hoạt động ở tầng code nào?

Trả lời: Cơ chế này được cài đặt trực tiếp trong vòng lặp đọc file của máy gửi tại file src/main/p2p/transfers.ts. Trước khi đọc và phát đi từng khối nhị phân 16 KiB, máy gửi luôn gọi isPeerAuthorized(groupId, remotePeerId, remoteSessionId, fileId). Nếu người dùng gỡ quyền nhóm trong giao diện Library khi file đang truyền dở, hàm kiểm tra sẽ trả về false ngay ở khối tiếp theo. Luồng phát dữ liệu lập tức bị hủy bỏ và gửi lỗi FORBIDDEN sang bên nhận, chặn đứng việc tải nốt phần còn lại.

❓
Câu 31: Quá trình cam kết file tải về (Atomic Commit) sử dụng lệnh `link()` và `unlink()` diễn ra như thế nào? Tại sao bắt buộc phải bắt lỗi `EEXIST`?

Trả lời: Khi tải file: (1) Dữ liệu được ghi vào file tạm ẩn .<filename>.tmp.<transferId>; (2) Mã băm SHA-256 được tính toán theo luồng và so sánh với mã băm ban đầu khi hoàn tất; (3) Hệ thống gọi lệnh link(partPath, destinationPath) để tạo hard link nguyên tử.
Bắt buộc bắt lỗi `EEXIST`: Nếu trên máy người dùng đã có sẵn file trùng tên, lệnh link() sẽ quẳng lỗi mã EEXIST. Hệ thống bắt mã lỗi này và hủy thao tác với mã DESTINATION_EXISTS, bảo đảm không bao giờ ghi đè làm mất dữ liệu quan trọng có sẵn của người dùng. Sau đó, lệnh unlink(partPath) được gọi để dọn dẹp file tạm.

❓
Câu 32: Phân hệ tìm kiếm `Search.tsx` thực hiện gom nhóm Swarm (Swarm Aggregation) như thế nào và người dùng được hưởng lợi gì từ cơ chế này?

Trả lời: Khi nhiều peer cùng chia sẻ một file, kết quả tìm kiếm thô sẽ trả về nhiều bản ghi riêng rẽ. Search.tsx sử dụng Map gom các kết quả trùng mã băm SHA-256 và kích thước file theo khóa ${item.file.sha256}:${item.file.size} thành một đối tượng GroupedResult.
Lợi ích: (1) Giao diện hiển thị gọn gàng, mỗi file duy nhất chỉ chiếm một hàng; (2) Người dùng xem được toàn bộ danh sách các nguồn sở hữu (Sources) và có thể chủ động chọn tải từ peer có kết nối Direct tốc độ cao thay vì node phải đi vòng qua relay TURN.

Tóm tắt & Lời khuyên trước khi bảo vệ vấn đáp

  1. Nắm chắc ranh giới bảo mật: Luôn nhấn mạnh sự tách biệt giữa 3 tiến trình, vai trò của contextBridge và bộ lọc 4 tầng của validateSender.
  2. Hiểu rõ bản chất toán học: Nắm vững công thức băm SHA-256 kết hợp giữa peerId và supernodeId trong thuật toán HRW và lý do tại sao nó vượt trội hơn Consistent Hash Ring về tính tối thiểu xáo trộn.
  3. Giải thích được cơ chế chống tràn bộ nhớ: Nhớ các con số quan trọng: chunk 16 KiB, ACK 256 KiB, trần đệm 512 KiB, thời hạn thuê 6000ms và bộ giới hạn 60 token của máy chủ Signaling.
  4. Tự tin mở bảng tra cứu mã nguồn ở Mục 3 để dẫn chứng trực tiếp file và hàm khi ban giám khảo yêu cầu kiểm tra code thực tế!
