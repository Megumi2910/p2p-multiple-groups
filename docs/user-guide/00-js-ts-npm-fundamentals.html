Nền Tảng JS/TS, Node.js, npm & Cẩm Nang Lệnh CLI

Tài liệu nhập môn chuyên sâu bằng tiếng Việt: giải thích từ gốc rễ cách JavaScript, TypeScript, Node.js và npm phối hợp trong dự án p2p-multiple-groups, kiến trúc 3 tiến trình Electron và ý nghĩa chi tiết của toàn bộ 16 lệnh CLI.

💡
Dành cho kỹ sư mới

Nếu bạn chưa có nhiều kinh nghiệm về TypeScript hoặc Electron, hãy đọc kỹ Phần 1 và Phần 2 để nắm vững luồng biên dịch trước khi bắt đầu thực thi các lệnh ở Phần 4 và Phần 5.

1. Nền tảng cốt lõi: JS, TS, Node.js và npm

Dự án kết hợp nhiều công nghệ hiện đại. Dưới đây là vai trò cụ thể của từng thành phần trong bức tranh tổng thể:

1.1. JavaScript (JS) — Ngôn ngữ thực thi chính

JavaScript là ngôn ngữ chạy đơn luồng (single-threaded) dựa trên cơ chế vòng lặp sự kiện bất đồng bộ (Non-blocking Event Loop). Nguyên lý quan trọng nhất: Cả trình duyệt Chromium (phần hiển thị giao diện) và môi trường Node.js (phần máy ảo P2P và máy chủ Signaling) đều chỉ hiểu và chạy trực tiếp mã JavaScript thuần túy.

Trong dự án này, toàn bộ mã nguồn tuân theo chuẩn ECMAScript Modules (ESM) hiện đại, quy định bởi dòng "type": "module" trong package.json: 

// Sử dụng cú pháp import / export chuẩn ESM
import { MultiGroupPeerStore } from './peer-store-v2.js';
export const engine = new PeerEngine();

1.2. TypeScript (TS & TSX) — Bản thiết kế kiểu dữ liệu tĩnh

JavaScript thuần không có kiểu dữ liệu tĩnh; lỗi truyền sai tham số chỉ phát hiện khi ứng dụng đang chạy (Runtime Error). Trong một hệ thống P2P phức tạp, lỗi runtime khi giải mã gói tin WebRTC sẽ làm đứt kết nối mạng của cả cụm ngang hàng.

TypeScript bổ sung "bản thiết kế kiểu" (Static Types) phía trên JavaScript. Ví dụ interface GroupInvitation trong src/shared/p2p.ts bảo đảm mọi lời mời tham gia nhóm đều phải đầy đủ các thuộc tính bắt buộc: 

export interface GroupInvitation {
  version: 2;
  groupId: string;
  groupName: string;
  signalingUrl: string;
  token: string;
  createdAt: number;
  expiresAt?: number;
}

File đuôi .tsx là TypeScript kết hợp cú pháp giao diện JSX của React 19, cho phép viết các component như <button onClick={joinGroup}>Gia nhập</button> trực tiếp bên trong logic xử lý.

⚡
Hai cơ chế xử lý TypeScript trong dự án này
  • Kiểm tra lỗi tĩnh (Typechecking): Sử dụng lệnh npm run typecheck (gọi tsc --noEmit). Trình biên dịch TypeScript chỉ kiểm tra tính hợp lệ của kiểu dữ liệu trong bộ nhớ, tuyệt đối không sinh ra bất kỳ file nào trên ổ cứng.
  • Chuyển đổi để chạy thực tế:
    • Node.js Native Type Stripping: Với các file chạy trực tiếp như test (tests/*.test.ts) hay signaling server (services/signaling/index.ts), Node.js >=24.12.0 tự động lột bỏ khai báo kiểu TS trong RAM và chạy thẳng mã JS mà không cần bước build trung gian.
    • Electron Desktop Build: electron-vite (kết hợp Vite, esbuild, Rollup) dịch và gom toàn bộ mã nguồn thành các file tối ưu trong thư mục ./out/.

1.3. Node.js (>=24.12.0) — Môi trường chạy JS/TS ngoài trình duyệt

Node.js cho phép JavaScript vận hành như một ngôn ngữ hệ thống trên Windows, macOS và Linux. Nó cung cấp:

  • Truy cập hệ thống tập tin cục bộ (node:fs) để đọc file chia sẻ và ghi trạng thái peer-state.json.
  • Socket mạng đa kênh: WebSocket (ws) và WebRTC data channel (werift).
  • Mã hóa bảo mật cao (node:crypto) để băm dữ liệu SHA-256 từng chunk 16 KiB.
  • Trình chạy kiểm thử tự động tốc độ cao tích hợp sẵn (node:test).

1.4. npm và bộ ba quản lý thư viện

Thành phần Vai trò trong dự án Đưa lên Git?
package.json Bảng kê khai thông tin dự án, danh sách lệnh tắt (scripts), các thư viện chạy thật (dependencies: react, werift, ws) và công cụ phát triển (devDependencies: electron, vite, typescript). Có
package-lock.json Sổ cái khóa cứng chính xác số phiên bản và mã băm toàn vẹn (integrity hash) của từng thư viện con để đảm bảo mọi máy tính chạy npm install đều ra kết quả giống hệt nhau. Có
node_modules/ Kho chứa toàn bộ mã nguồn thực tế của các thư viện bên thứ 3 tải từ Internet về máy. Rất nặng và tự sinh ra khi gõ npm install. Không (luôn nằm trong .gitignore)

2. Kiến trúc 3 tiến trình Electron và hệ thống 3 file tsconfig

2.1. Phân chia 3 tiến trình độc lập

Để đảm bảo an toàn tối đa cho máy tính của người dùng, ứng dụng desktop được chia làm 3 tiến trình với ranh giới an ninh nghiêm ngặt:

2.2. Vai trò của 3 file tsconfig

Dự án sử dụng cơ chế Project References của TypeScript để áp dụng các luật kiểm tra kiểu phù hợp cho từng môi trường:

  • tsconfig.json: File mồi trung tâm, điều phối tham chiếu tới 2 file con bên dưới.
  • tsconfig.node.json: Quy định kiểu cho môi trường Node.js ("types": ["node"]). Áp dụng cho: src/main/, src/preload/, src/shared/, services/, scripts/, tests/, và electron.vite.config.ts. Bật "erasableSyntaxOnly": true để tương thích hoàn toàn với Node 24.
  • tsconfig.web.json: Quy định kiểu cho môi trường trình duyệt React ("jsx": "react-jsx", "types": ["vite/client"]). Áp dụng cho src/renderer/ và src/shared/. Ngăn chặn việc gọi nhầm các API hệ thống của Node.js từ giao diện.

4. Giải thích chuyên sâu từng lệnh: Tại sao có, nó làm gì, cờ/tham số là gì?

Nhóm 1: Cài đặt

1. npm install

Đọc package-lock.json, tải các thư viện về thư mục node_modules/ và thực hiện liên kết native modules. Dự án cấu hình mục allowScripts trong package.json để cấp quyền cho esbuild biên dịch nhị phân tối ưu hóa riêng cho hệ điều hành của bạn.

Nhóm 2: Chạy & Đóng gói ứng dụng Desktop

2. npm run dev (Lệnh ngầm: electron-vite dev --watch)

Khởi động môi trường phát triển: bật máy chủ Vite tại http://127.0.0.1:5173 phục vụ Hot Module Replacement (HMR) cho giao diện React; đồng thời biên dịch nóng Main Process và Preload Script với cờ --watch (tự khởi động lại nếu bạn sửa mã ở tiến trình chính).

3. npm run build (Lệnh ngầm: npm run typecheck && electron-vite build)

Toán tử && bảo đảm chỉ đóng gói khi bước kiểm tra kiểu (typecheck) không có bất kỳ lỗi nào. Sau đó electron-vite build sẽ đóng gói:

  • src/main/index.ts → ./out/main/index.js (ES Module)
  • src/preload/index.ts → ./out/preload/index.cjs (CommonJS)
  • src/renderer/ → ./out/renderer/ (HTML tĩnh và JS/CSS đã nén minified)

4. npm run start (Lệnh ngầm: electron-vite preview)

Chạy thử ứng dụng desktop Electron trực tiếp từ thư mục ./out/ giống hệt môi trường thực tế của người dùng cuối, không thông qua dev server Vite. Bắt buộc phải chạy npm run build trước.

Nhóm 3: Kiểm tra kiểu dữ liệu TypeScript (Typechecking)

5. npm run typecheck:node (tsc --noEmit -p tsconfig.node.json --composite false)

Ý nghĩa từng cờ:

  • tsc: Trình biên dịch TypeScript Compiler.
  • --noEmit: Chỉ kiểm tra lỗi trong RAM, tuyệt đối không tạo ra file mới trên ổ cứng.
  • -p tsconfig.node.json: Đọc cấu hình từ file Node chuyên biệt (kiểm tra main, preload, shared, services, scripts, tests).
  • --composite false: Tắt chế độ build composite để ép kiểm tra trực tiếp nhanh nhất.

6. npm run typecheck:web (tsc --noEmit -p tsconfig.web.json --composite false)

Tương tự lệnh trên, nhưng áp dụng cho tsconfig.web.json để kiểm tra giao diện React 19 trong src/renderer/ (kiểm tra props, hooks, cú pháp thẻ JSX).

7. npm run typecheck (npm run typecheck:node && npm run typecheck:web)

Chạy kiểm tra toàn diện cả hai môi trường Node và Web. Dừng ngay lập tức nếu xuất hiện bất kỳ cảnh báo lỗi kiểu nào.

Nhóm 4: Bộ kiểm thử tự động 3 tầng

8. npm run test:unit

Sử dụng trình chạy test siêu tốc tích hợp sẵn node --test để chạy tuần tự 6 file unit test: theme-store, credential-store, peer-store-v2 (atomic rename chống hỏng file), profile-migration (tự nâng cấp cấu hình V1 lên V2), signaling-config và p2p-protocol.

9. npm run test:p2p

Chạy tuần tự 9 file test tích hợp mạng ngang hàng: kiểm tra WebSocket server, tự động gia hạn lease heartbeat, bắt tay WebRTC thật trong bộ nhớ qua werift, chia sẻ file, phân quyền grant, băm SHA-256 từng chunk 16 KiB, chịu lỗi đứt mạng giữa chừng (survival) và cô lập đa nhóm (multi-group security).

10. npm run test:e2e (node --test tests/electron-e2e.test.ts)

Khởi động ứng dụng Electron thật, kết nối qua Chrome DevTools Protocol (CDP) để tự động điều khiển chuột/phím, mở Command Palette (Ctrl+K), duyệt qua tất cả các màn hình và kiểm tra kết xuất giao diện.

11. npm test

Chạy liên tiếp cả 3 tầng kiểm thử: npm run test:unit && npm run test:p2p && npm run test:e2e.

Nhóm 5: Vận hành Signaling & Tạo mã mời

12. npm run signal:start (node --env-file-if-exists=.env services/signaling/index.ts)

Cờ --env-file-if-exists=.env là tính năng native của Node.js giúp tự động nạp file cấu hình môi trường mà không cần cài thêm thư viện dotenv. Khởi chạy máy chủ WebSocket Signaling tại ws://127.0.0.1:8787/signal.

13. npm run signal:invite (node --env-file-if-exists=.env scripts/create-invite.ts)

Cách truyền tham số qua ký hiệu --: 

npm run signal:invite -- --group-id=engineering-team --group-name="Đội Kỹ Thuật"

Ký hiệu -- báo cho npm biết hãy chuyển toàn bộ tham số phía sau vào cho script xử lý để sinh ra chuỗi JSON lời mời GroupInvitation V2 có chữ ký bảo mật.

Nhóm 6: Tài liệu & Đảm bảo chất lượng

14. npm run docs:open (node scripts/open-docs.js)

Tự động nhận diện hệ điều hành (Windows cmd /c start, macOS open, Linux xdg-open) để mở cổng tài liệu docs/index.html trên trình duyệt web. Hỗ trợ cờ npm run docs:open -- --dry-run để kiểm tra trong CI.

15. npm run docs:screenshots (node scripts/capture-docs-screenshots.ts)

Dựng cụm P2P ảo với dữ liệu mẫu, mở Electron và dùng CDP tự động chụp lại 6 ảnh giao diện sắc nét lưu vào thư mục docs/assets/.

16. node scripts/verify-html-docs.js

Bộ công cụ kiểm tra tự động: duyệt qua tất cả 21 file HTML, kiểm tra từng đường dẫn liên kết tương đối, ảnh, script và mọi thẻ neo #id nội bộ để đảm bảo tài liệu không có bất kỳ liên kết hỏng nào.

5. Các quy trình thực hành chuẩn cho người mới bắt đầu

Quy trình 1: Cài đặt và khởi chạy ứng dụng lần đầu

# 1. Di chuyển vào thư mục dự án
cd p2p-multiple-groups

# 2. Kiểm tra phiên bản Node.js (bắt buộc >= 24.12.0)
node -v

# 3. Cài đặt toàn bộ thư viện dependencies
npm install

# 4. Kiểm tra kiểu dữ liệu để đảm bảo môi trường sạch
npm run typecheck

# 5. Khởi động ứng dụng ở chế độ phát triển
npm run dev

Quy trình 2: Tự mở mạng P2P và thử nghiệm chia sẻ file trên máy cá nhân

Bạn có thể mô phỏng một mạng P2P gồm 2 máy tính kết nối với nhau ngay trên 1 chiếc laptop:

# CỬA SỔ TERMINAL 1: Bật máy chủ Signaling
npm run signal:start

# CỬA SỔ TERMINAL 2: Tạo mã mời cho nhóm thử nghiệm
npm run signal:invite -- --group-id=nhom-test --group-name="Nhóm Test"
# -> Sao chép toàn bộ chuỗi JSON in ra trên màn hình

# CỬA SỔ TERMINAL 3: Bật Peer A
npm run dev
# -> Vào mục "Network & Groups" -> Dán chuỗi JSON -> Bấm "Join Group"
# -> Vào mục "Library" -> Bấm "Add File" để chọn file và cấp quyền chia sẻ cho nhóm

# CỬA SỔ TERMINAL 4: Bật Peer B (chạy bản preview độc lập)
npm run build
npm run start
# -> Vào mục "Network & Groups" -> Dán mã mời -> Bấm "Join Group"
# -> Vào mục "Search & Discovery" -> Tìm kiếm file -> Bấm "Download"
# -> Vào mục "Transfers" để quan sát các khối 16 KiB được truyền trực tiếp qua WebRTC!

Quy trình 3: Kiểm tra toàn diện trước khi commit / bàn giao code

# Bước 1: Kiểm tra kiểu dữ liệu tĩnh (Bắt buộc không có bất kỳ lỗi TS nào)
npm run typecheck

# Bước 2: Chạy trọn bộ 3 tầng kiểm thử tự động (Unit, P2P, E2E)
npm test

# Bước 3: Kiểm tra tính toàn vẹn của hệ thống tài liệu HTML
node scripts/verify-html-docs.js
